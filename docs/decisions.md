# Drop: decisions and research

Why Drop works the way it does, and what the research before v1 found. Moved here from the workspace plan (`studio/drop/plan.md`, deleted 2026-11-19 once v1 shipped; git keeps it). `AGENTS.md` is the map of the code and the rules. Design: [Drop boards](https://artifacts.niduslabs.dev/drop/boards). Research files: `.claude/research/` (gitignored): `dmg-parsing.md` (format, licences, CIS), `existing-apps.md` (EasyDMG and others).

## Decided (2026-11-16)

- **A Nidus Labs product named Drop**, shown as **"Drop: DMG Installer"** on niduslabs.dev and GitHub, "by Nidus Labs" as a byline only (name check 2026-11-16, `.claude/research/name-check.md`). No live US mark covers "Drop" for this kind of software; DropDMG's only US filing was abandoned in 2005. "Drop" can't be owned. Never "Drop DMG"; no AirDrop-like copy or visuals; no box icon. EU, UK and India searched too: no conflict for this kind of software; Dropbox opposes plain "drop" software marks in the EU, so never register DROP there. The remaining captcha-only lookups were judged not needed (2026-11-16). Backup name: Fledge.
- **Reads DMGs directly** with our own Swift reader: UDIF container, partition map, HFS+ and APFS, both filesystems built together for v1. Every compression Apple's tools can produce (raw, zero, zlib, bzip2, lzma, lzfse, ADC). Raw images without a UDIF wrapper are read directly too.
- **Fallback is a hidden mount, not a hand-off to Finder:** anything the reader can't handle (an unknown future compression, encrypted images after asking for the password, sparse or pre-10.2 images, decmpfs files, encrypted APFS) is mounted with nothing shown in Finder or the sidebar (`diskutil image attach`; `hdiutil attach` is deprecated), copied through the same extractor (quarantine, marker, ticket), then unmounted. Still one click. The C libraries that do this are GPL or LGPL, so we write our own and use CIS (MIT) and `dpp` (MIT) as references only.
- **What sets it apart from EasyDMG:** it notices new DMGs in Downloads and asks first, shows who signed the app before install, and keeps quarantine.
- **No Dock or menu bar icon** (revised 2026-11-16, replacing the temporary menu bar icon): a new download shows a non-activating popup at the top right of the screen with the active menu bar, sliding in from the right edge, with "Drop" in its top line; a double-clicked or Open With image opens a normal centred window that takes focus. Settings opens when Drop is opened again; pausing is the Ask switch; Quit Drop is at the bottom of Settings. Onboarding floats above other windows (macOS prompts still above it) and shows in Command-Tab while open. The same goes for Settings and the centred install window: while any of them is open Drop has a Dock icon and is in Command-Tab (regular policy), back to no Dock icon when the last one closes (decided 2026-11-16: with no menu bar icon, a window that slips behind others would otherwise be unreachable). The top-right popup never changes it. Every control in onboarding, the popup and the centred window is reachable with the Tab key (moss focus ring, even with macOS Keyboard navigation off); Space presses the focused control, Return the primary.
- **No recent-installs list** (decided 2026-11-17): Settings has Watching, Installing, General and Drop only. The handled-DMG list stays (it stops repeat prompts).
- **No "Update on Quit"** (decided 2026-11-17): updating a running app stays one step, Quit and Update. No deferred swap and no replacing an app while it runs.
- **Look** (decided 2026-11-16): the Nidus component kit (moss accent, paper secondary, capsule buttons, radius-8 selects and fields, switches only, never checkboxes; Manrope for onboarding headings and the byline). Dark mode is **ink glass**: behind-window blur with an ink tint (#1C1B22 at 86%), solid ink when Reduce Transparency is on. App icon: **The Slot** (an app tile carrying the Nidus mark drops into a glowing moss slot), generated by the assets repo into `assets/apps/drop/`.
- **Design inspiration from Purge** (MIT, `.claude/research/purge-design.md`): techniques and values re-implemented, not its identity. Popup blur-slide in, status blur-swap, drawn Installed check with a minimum hold, staging steps 550 ms apart, rolling numbers, button motion rules, capsule actions, Reduce Motion fallbacks.
- **Do what macOS does with quarantine:** every installed app keeps it, as after a Finder drag, so Gatekeeper runs its usual first-open check. Opt-in "Skip the 'downloaded from the Internet' prompt" (off by default, decided 2026-11-16): only for notarized apps that pass Drop's check, never for Install Anyway; Drop writes quarantine pre-approved (the bit clicking Open sets) instead of deleting it. Tested 2026-11-16 (`.claude/research/preapproved-spike.md`): with quarantine written as the DMG's value plus `0x0040 | 0x0100` (raw `setxattr`, no supported API), macOS 27 still checks the signature and notarization at first launch (ticket fetched online when not stapled), runs in place, and skips XProtect's up-front scan exactly as it does after a real Open (notarized apps skip it either way). Only set `0x0040` after `SecAssessmentCreate` (execute) says Notarized Developer ID; otherwise `0x0100` only. Never delete the attribute. Retest each major macOS. Drop adds the do-not-translocate flag a Finder move sets, and copies the DMG's stapled ticket into an app that has none. Drop's own signature check before install is extra, not a replacement. A broken signature is a hard stop.
- **Ready before you click** (decided 2026-11-16): when a DMG finishes downloading, Drop reads it, checks the signature and stages the app at low priority while the popup shows. Install is then a rename into place. Not now deletes the staged copy. Staging lives on the same volume as the destination so the final move is a rename, never a copy.
- **Runs in the background as a login item** (decided 2026-11-16): `SMAppService.mainApp`, on by default ("Open Drop at login"), listed in System Settings › Login Items. No Dock icon or window (`LSUIElement`); opening Drop while it runs shows Settings. It must be running to watch Downloads. Chosen over a launchd agent with `WatchPaths` (zero idle memory, but it fires on every change in Downloads, adds 0.1–0.3 s before the popup and needs re-registering when the folder changes). Revisit if measured idle memory is high.
- **Gentle in the background, fast on Install** (decided 2026-11-16): never slow down what the user is doing.
  - Staging while the popup shows runs at background QoS with 2–3 decode threads, throttled disk I/O (`setiopolicy_np` IOPOL_THROTTLE), and bounded memory. Measured 2026-11-16 (`.claude/research/impact-bench.md`, Round 2): utility decode (3 decoders), writes paced at 200 MB/s until Install, 8 MiB read-ahead and a 32 MiB cache; CPU impact 2.6%, Docker ready in 14.7 s, Install mid-way to installed 1.8 s for GIMP (accepted: under 1.5 s would mean verifying while copying).
  - **Memory target: under about 170 MB during a big install, back to idle after** (was ~100 MB; measured 131-136 MB for GIMP, 166 MB for Docker then GIMP; going lower slows installs).
  - **Disk impact:** the saturating uncached-read benchmark drifted from 10.5% to 26-30% on unchanged code as the SSD tired, so it's a stress test, not the target. The target is under 3% against realistic foreground disk use (a build, copying a photo folder), measured on a rested SSD. Measured on a rested SSD (Round 3): a clean build shows no slowdown, a 3 GB folder copy 2.9%, a cold read of 12k small files 6.7% (about 0.1 s, only in the ~15 s after a big download); accepted. No adaptive backoff (decided 2026-11-16: not worth the complexity); the 200 MB/s pacing and background QoS are the whole mechanism, and the realistic measurement is a check, not a gate.
  - Low Power Mode, or a thermal state of serious or worse: show the summary (`waitingToPrepare`) and stage only on Install; pause and resume as the conditions change. Built 2026-11-16.
  - Install clicked: raise to user-initiated QoS and all cores for whatever is left.
  - Idle: no polling. FSEvents only, ignore partial downloads (`.crdownload`, `.part`, `.download`), react to the finished `.dmg`.
- **Drop's own signature check stays** (decided 2026-11-16): it shows the signer before install, compares the developer with the installed copy on updates, refuses damaged apps before the old copy is touched, gates the skip-prompt setting and verifies the ticket before stapling. It runs during staging, so it costs no wait.
- **GPL-3.0, public repo `niduslabs-dev/drop`** (decided 2026-11-16). Not taking code contributions yet (taking them would need a contributor agreement to keep the option of selling or relicensing).
- **Not an App Store app** (decided 2026-11-16): shipped only from niduslabs.dev and GitHub Releases (`niduslabs-dev/drop`), Developer ID signed and notarized, not sandboxed (it writes to `/Applications` and reads Downloads). The App Store name and search concerns from the name check don't apply.

## v1 scope

Popup (found, installing, done), update and replace (old copy to the Trash, quit the running app first), not-notarized warning, hidden-mount fallback; "Can't install this one" only for `.pkg` (to Installer), and images that won't open at all ("Open disk image"); licence agreements shown by Drop (text or RTF, language picker) before Install, on both the direct and hidden-mount paths, never accepted silently; the Downloads watcher (configurable folder), trash the DMG after, open after install, Settings.

**Open With › Drop** (Alternate handler for disk images), and a Settings switch "Open disk images with Drop" that makes Drop the default for `.dmg` and hands it back to DiskImageMounter when off. Drop never asks on its own: first-launch onboarding (Welcome, Downloads, Open disk images with Drop?, Start at login?, Done) explains each permission and requests it only when the user agrees; Not now skips, and Settings can do it later. Drop's own "Open disk image" always opens with DiskImageMounter explicitly, so there is no loop. An explicit open shows the panel even for a DMG dismissed before.

**Later (v2):** privileged installs for root-owned apps, more than one app in an image.

## What the spike found (2026-11-16)

From `.claude/research/gatekeeper-spike.md`, `dmg-survey.md`, `benchmarks.md` and `write-bench.md`.

- **Quarantine:** write the DMG's quarantine value on every item with flag `0x0100` added (do not translocate, what a Finder move sets; inferred from behaviour, not documented). Without it our copies run translocated on every launch. The first-open prompt still shows. Retest on each major macOS release.
- **Ticket only on the DMG:** online, macOS fetches it and the app opens with the normal prompt. For offline, copy the DMG's stapled ticket into the staged app's `Contents/CodeResources` after checking it lists the app's cdhash (`stapler validate` then passes). Offline launch not tested; Jatin decided it isn't needed (2026-11-16).
- **Formats (34 DMGs):** all UDIF; HFS+ 31, APFS 3; zlib, bzip2, lzma, lzfse all seen, no ADC; GPT and APM; no decmpfs, hard links or resource forks; one licence agreement (Zed). Build HFS+ and APFS together. Test corpus: `.claude/samples/`. `.claude/research/scripts/survey.py` is a working Python reader to port.
- **Speed (benchmarks.md, M3 Pro):** parsing takes 0.01–0.07 s; decoding is the cost (lzma ~125 MB/s, bzip2 ~62 MB/s per core, zlib ~900, lzfse ~1,900); chunks are independent, 11 threads decode 7–8.5x faster. Mount path on a fresh download: Rectangle 0.36 s, Firefox 12.8 s, VLC 19.1 s, Docker 38.3 s (first attach verifies the checksum, ditto decodes on one core). Drop estimates: 0.06 s, 0.9 s, 0.8 s, 3.2 s. Many small files (GIMP, 12k files) make writing the bottleneck. Signature check 0.25–2.3 s either way.
- **Write path (write-bench.md):** POSIX `openat(O_CREAT|O_EXCL, final mode)` relative to an open staging dir fd, `write` in large blocks, `fsetxattr` for quarantine, `close`; 4 writer threads (8 and 11 were slower); no per-file `fsync`, never `F_FULLFSYNC` (GIMP 32 s); no `F_NOCACHE` or preallocation. GIMP 0.61 s vs 2.94 s in Python. Staging `….noindex/<uuid>/` on the destination volume, then `rename()` (under 1 ms). Cancel renames the staging folder aside and deletes it in the background (GIMP's delete takes 1.2 s). Estimated install work: GIMP ~0.7 s, Firefox ~0.7 s, Docker ~2.5 s, plus the signature check, all during the popup.
- **Speed rules for the build:** decode chunks in parallel; stream each file to disk as its chunks finish; the write path above; run the signature check alongside; a timing test in CI that fails if Drop is slower than the mount path on the corpus.
- **What the extractor keeps:** bytes, symlinks, permission bits and `com.apple.cs.*`, written into a fresh staging folder without following symlinks; checked with `SecStaticCodeCheckValidity` and `SecAssessmentCreate`, then moved into place in one step. The bar: `codesign --verify --deep --strict` matches a Finder drag for every sample.
- **Proof it stays out of the way:** stage Docker and GIMP in the background while a busy foreground workload runs; the foreground slows by under 3%.

- **Idle footprint (measured 2026-11-17, one hour, release build):** 17 MB average, 20.8 MB peak, 0.00% CPU. The always-running login item stays.
